# Pause, resume and plan usage

Read when the user pauses the delivery, a resource runs out, or `status` reports plan usage as economy or wait. The ledger commands run as the Ledger section of the manager says.

- `pause --text '<what to do on return>'` when the user pauses the delivery or a resource runs out, once you have stopped the agents (`TaskStop`) and committed each task worktree's work there yourself as `wip: <task> <what is done>` (it refuses otherwise); `resume` when work restarts lists the claims to dispatch again, each in its worktree at its tip, which the brief names as the origin.
- **A resource runs out** (memory, disk, a port, a quota) and a step is killed or blocked: do not wait for the user. Stop the agents that are building or testing (`TaskStop`) and the processes you started (by PID, never one you did not start), hold new dispatches, keep the heartbeat (while paused, it only checks the resource) and `pause` as above, its text also naming the resource, how much was free and how many copies were up (status lists it among the notes). Wait with a background command (Bash `run_in_background`) that checks the resource every few seconds and exits once it is back, so its completion wakes you without spending tokens while it waits; the heartbeat stays as the fallback if that command dies. Then `resume`, with fewer tasks in parallel when parallel work ran it out.
- **Plan usage**, which `status` gives when the mod records it: on economy, dispatch the `reviewer` with model `sonnet` and one copy at a time, with one `note` when it starts; on wait (the window plus what one run uses reaches the limit), dispatch nothing new and treat the agents in flight as a resource pause does: `TaskStop`, `wip:`, `pause` until the reset; delete the heartbeat, sleep the time `status` gives in a background command, then `resume` and create it again. On return after a reset, a claim whose agent the limit cut gets no `add`: commit what it left there as `wip:` and send it back to a `dev`.
